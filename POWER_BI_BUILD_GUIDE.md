# Power BI build guide

The repository includes `powerbi/measures.dax` and `powerbi/CreditRiskAnalyticsTheme.json`. A native `.pbix` cannot be generated by this project package; create it in Power BI Desktop by following these steps.

## 1. Prepare the data

1. Obtain a permitted copy of the historical LendingClub accepted-loan CSV; the raw file is not bundled because of size and provenance considerations.
2. Run the chunked preparation script (see README) to create `data/processed/lendingclub_sample.csv`.
3. Open Power BI Desktop → **Get data → Text/CSV** → select the normalized CSV. Rename the table to `FactLoans`.
4. Confirm `issue_date` is Date, `loan_amnt` / `annual_inc` are numeric, `term_months` is whole number, `dti` / `int_rate` are decimal numbers stored in percentage points, and `default_flag` is whole number 0/1.
5. Import the theme JSON with **View → Themes → Browse for themes**.
6. Add the measures from `powerbi/measures.dax`. Format `Default Rate`, `Average Interest Rate`, `Average DTI`, and the D/E + DTI measure as Percentage with 1 decimal. Format loan amounts and income as currency; counts as whole numbers.

## 2. Model and pages

For a simple single-table report, `FactLoans` is enough. For a star schema, add a calendar table with a one-to-many relationship `DimDate[Date]` → `FactLoans[issue_date]`; optionally add distinct dimension tables for grade, purpose and term. Keep the fact table at one row per loan.

### Page 1 — Executive Portfolio
- KPI cards: Total Loans, Default Loans, Default Rate, Total Original Loan Amount, Defaulted Original Loan Amount, Average Loan Amount, Average Interest Rate, Average DTI.
- Line chart: monthly/yearly originations by issue date.
- Bar chart: loan count by grade.
- Slicers: issue date, grade, term and purpose.

### Page 2 — Segment Risk
- Bar chart: default rate by grade (natural A→G order), show loan count in tooltip.
- Matrix: income band × grade with default rate and loan count.
- Column chart: default rate by DTI band and by term.
- Table for Grade D/E + DTI >25%, showing the rate and denominator.

### Page 3 — Data Quality & Model Notes
- Quality checks from `outputs/data_quality.json`.
- A note defining eligible outcomes and time window.
- If model metrics are shown, include test period, baseline, validation-selected threshold and caveats.

## 3. Quality review

- Check total loan count against the normalized source and SQL `COUNT(*)`.
- Reconcile defaults to `SUM(default_flag)` and the default rate to defaults / eligible resolved loans.
- Ensure all active/unresolved statuses were excluded from this binary study and all displayed charts use the same eligible population.
- Use a visible note that all packaged demo records are synthetic. Replace demo output with validated source-data outputs before sharing empirical claims.
